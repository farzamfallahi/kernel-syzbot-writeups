# Linux kernel: syzbot lockdep reports, reproduced and analysed

Two syzbot-reported lockdep deadlock warnings, each reproduced on a kernel I built
myself, root-caused, and tested against a candidate fix inside a QEMU/KVM VM with
`PROVE_LOCKING` enabled.

| # | syzbot report | Subsystem | Status |
|---|---------------|-----------|--------|
| 1 | possible deadlock in `__d_alloc_parallel` ([bug page](https://syzkaller.appspot.com/bug?extid=52aa59fd5e3cd8a19dd7)) | VFS dcache / overlayfs | Root cause found, two fixes verified. An upstream fix by Neil Brown was posted on 2026-10-02, before I finished, so I did not send a competing patch. |
| 2 | possible deadlock in `set_blocksize` ([bug page](https://syzkaller.appspot.com/bug?extid=5c01398781fb51df783a)) | btrfs / block layer | Splat reproduced; candidate patch removes it. Not yet submitted upstream (see bug2 notes). |

## Method

1. Take the syzbot C reproducer and config; build a minimal kernel with lockdep (`make O=../build`).
2. Boot it in QEMU (`-accel kvm`, virtio-scsi, `snapshot=on` so the disk image is never modified).
3. Reproduce the splat on an **unpatched** kernel first (control).
4. Apply the change, rebuild, rerun, and compare.

`harness/run-vm-test.sh` is the VM launcher used for every run.

## Layout

- `bug1-d_alloc_parallel/` - analysis, patches, logs
- `bug2-set_blocksize/` - analysis, patch, repro, logs
- `harness/` - VM launcher
